# v0.4.0 BatchGet in a Linux container

On November 19, 2026, one caller reading 32 distinct 64 KiB values with
Linux storage I/O observed had a median latency of 1.93 ms at read limit 1,
1.20 ms at the default 8, and 1.37 ms at 32. Eight callers sharing one DB
completed 456, 784 and 825 requests/s respectively.

## Storage reads

The table shows medians across six rounds. Each cell aggregates 256 public
BatchGet calls per round. Latency excludes validation. Throughput includes
the value and order checks performed between calls.

| Value | Clients | Read limit | p50 ms | p95 ms | p99 ms | Requests/s |
|---|---:|---:|---:|---:|---:|---:|
| 64 B | 1 | 1 | 0.913 | 1.245 | 1.449 | 1,254 |
| 64 B | 1 | 8 | 0.471 | 0.661 | 1.148 | 2,346 |
| 64 B | 1 | 32 | 0.487 | 0.843 | 1.106 | 2,218 |
| 64 B | 8 | 1 | 8.216 | 10.840 | 11.070 | 1,112 |
| 64 B | 8 | 8 | 2.832 | 4.077 | 4.767 | 3,331 |
| 64 B | 8 | 32 | 2.327 | 5.022 | 8.607 | 3,280 |

For eight callers with 64 B values, raising the limit from 8 to 32 reduced
p50 and increased p99 in all six paired rounds. At 64 KiB the corresponding
p50 and p99 improved in four of six rounds. Individual client p99 with 32
samples in a round equals that client's slowest call.

## Warm and duplicate controls

Linux charged storage reads to the process in all 72 fixture-evicted trials.
The median charged volume per trial was 33.39 MiB for the padded 64 B
records and 513.00 MiB for the 64 KiB records. All 72 OS-warm,
72 tarp-cache-hit and 72 duplicate-input trials had zero charged read bytes.
On the OS-warm 64 B workload, one caller's p50 at limits 1 and 8 was 18 µs
and 22 µs respectively. The faster setting changed when fetching data
required I/O.

The driver verified the returned bytes and input order in all 73,728 requests.
The duplicate controls observed one miss and 31 duplicate inputs for every
32-slot call. The all-hit controls observed 32 hits per call. The raw data
includes per-client samples, Stats deltas, wall time and storage counters.

## Environment and reproduction

- Engine `234e25616cd23fb14d9fe67fd1ae4de548407b86` (v0.4.0).
- Go 1.27.4, linux/arm64, GOMAXPROCS=8. Official Go image
  `docker.io/library/golang@sha256:4fa7c968ba93f1635670522dbb01a2c78150443e1385746924566079f36570ea`.
- Docker Desktop 29.5.3 with a 16-vCPU Linux VM, kernel 6.12.76-linuxkit,
  private ext4 volume on virtual device `/dev/vda1`. The process counter
  measures Linux-attributed storage bytes including readahead. The underlying
  host can still cache virtual disk contents.
